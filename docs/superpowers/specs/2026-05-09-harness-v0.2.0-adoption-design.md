# Sidecar — Harness v0.2.0 Memory Adoption Design Spec

**Date:** 2026-05-09
**Status:** Draft
**Builds on:** Phase 3 (memory) — complete

---

## 1. Overview

Harness v0.2.0 ships three subsystems sidecar built in-house during Phase 3:
writable memory (`tool/memory`), self-improvement reviewer (`runtime.Review`),
and a lifecycle hook (`LifecycleHooks.OnStop`) that ties them together.

This spec replaces sidecar's `internal/memory/reflect.go` (JSON-envelope
extraction) and `loop.launchReflect` (manual goroutine) with the
upstream Review primitive driving a `MemoryStore` adapter over the
existing pgvector backend.

The pgvector schema, embedding providers, and pre-loop semantic
retrieval (`memory.Retrieve`) stay as-is. What changes is **how memories
get written**: from a one-shot JSON-parse model call after each task to
in-loop tool calls invoked by a reviewer agent.

**Two deliverables:**

1. `internal/memory/store_adapter.go` — implements `harnessmem.MemoryStore`
   over `*store.DB` + `EmbeddingProvider`.
2. `internal/loop/loop.go` rewiring — register `harnessmem.MemoryTool` for
   the coding agent and add `LifecycleHooks.OnStop` that fires
   `runtime.Review`.

**Deleted:** `internal/memory/reflect.go`, `internal/memory/reflect_test.go`,
and the `Loop.launchReflect` method.

---

## 2. Goals / Non-goals

### Goals

- Replace JSON-parse extraction with tool-call extraction. The reviewer
  agent calls `memory.save(content, tags)` directly; no envelope to
  parse, no fallback path.
- Reuse the existing pgvector backend without schema migration of the
  embedding column. Additive columns only (`updated_at`, `origin`).
- Map sidecar's category model (episodic/semantic/procedural) onto
  harness's tag model: `tags[0]` is the category. Default "semantic"
  when the agent omits a category tag.
- Keep the foreground coding agent able to write memory mid-task — not
  only the reviewer. Saves a round-trip when the agent learns something
  it wants to remember immediately.
- Cut over hard. No parallel reflect path. If a reviewer call fails to
  emit any saves, that signal produces no memory — same blast radius as
  a JSON-parse failure today.

### Non-goals

- **Skills (`tool/skills`).** Procedural memory stays in the memory table
  for now. Migrating procedural entries to a SkillStore is a separate
  spec; doing both at once would conflate two refactors.
- **Policies.** The `policies` table and `StorePolicy`/`GetPolicies` API
  is untouched. Policies are loaded as a flat list into context; there
  is no agent-write path today and none planned in this spec.
- **Pre-loop retrieval.** `memory.Retrieve` continues to query pgvector
  directly via `db.SearchMemory` and inject a markdown block into the
  system prompt. The MemoryStore adapter handles only writes.
- **Embedding for tool-saved entries on the reviewer's hot path.** The
  adapter calls `EmbeddingProvider.Embed` synchronously inside `Save`.
  An async embed queue is a future optimization, not v1.
- **Cross-workspace memory.** Each `*HarnessStoreAdapter` is bound to
  one workspace ID at construction; multi-tenant fan-out is out of
  scope.

## 3. Architecture

```
┌────────────────────────────────────────────────────────────────────┐
│ loop.Loop.Run                                                      │
│                                                                    │
│  triage → memory.Retrieve (pgvector) → BuildSystemPrompt           │
│         → BuildRuntime(tools = file/bash/edit + memory.MemoryTool) │
│         → rt.Run                                                   │
│         → LifecycleHooks.OnStop fires:                             │
│              go runtime.Review(context.Background(), rt, ReviewSpec{│
│                  Prompt: buildReviewerPrompt(task, events),        │
│                  Tools:  registry containing memory.MemoryTool,    │
│                  Model:  models.Triage,  // haiku, cheap           │
│              })                                                    │
│                                                                    │
└────────────────────────────────────────────────────────────────────┘
            │                                       │
            ▼                                       ▼
   harnessmem.MemoryTool                  harnessmem.MemoryTool
   (foreground saves)                     (reviewer saves)
            │                                       │
            └────────────────┬──────────────────────┘
                             ▼
              memory.HarnessStoreAdapter
              (implements harnessmem.MemoryStore)
                             │
                             ▼
              ┌──────────────┴────────────────┐
              │                               │
              ▼                               ▼
       *store.DB                    EmbeddingProvider
       (pgvector writes)            (OpenAI / Voyage)
```

The same `MemoryTool` instance is registered in both the foreground
coding agent's registry and the reviewer's restricted registry. Both
funnel through the adapter to the same database row — origin column
distinguishes them.

## 4. `internal/memory/store_adapter.go` — new file

```go
package memory

import (
    "context"
    "fmt"

    "github.com/google/uuid"
    harnessmem "github.com/sausheong/harness/tool/memory"
    "github.com/sausheong/sidecar/internal/store"
)

// HarnessStoreAdapter implements harnessmem.MemoryStore over the
// pgvector-backed *store.DB. It is bound to one workspace at
// construction; cross-workspace operations require a separate adapter.
type HarnessStoreAdapter struct {
    db          *store.DB
    embeddings  EmbeddingProvider
    workspaceID uuid.UUID
}

// NewHarnessStoreAdapter constructs an adapter bound to one workspace.
// embeddings must be non-nil; if it returns an error during Save, the
// underlying row is not written.
func NewHarnessStoreAdapter(db *store.DB, embeddings EmbeddingProvider, workspaceID uuid.UUID) *HarnessStoreAdapter {
    return &HarnessStoreAdapter{db: db, embeddings: embeddings, workspaceID: workspaceID}
}

// Save embeds the entry's Content and inserts a row.
//   - Category derives from tags[0] when present and recognized
//     ("episodic" | "semantic" | "procedural"). Otherwise "semantic".
//   - Origin is read from ctx via harnessmem.OriginKey, defaulting to
//     "agent" when unset. runtime.Review sets it to "review".
//   - The returned Entry has ID set to the row's UUID; CreatedAt and
//     UpdatedAt come from the database.
func (a *HarnessStoreAdapter) Save(ctx context.Context, e harnessmem.Entry) (harnessmem.Entry, error) {
    if e.Content == "" {
        return harnessmem.Entry{}, harnessmem.ErrInvalidContent
    }
    category := categoryFromTags(e.Tags)
    origin := originFromCtx(ctx)

    embeds, err := a.embeddings.Embed(ctx, []string{e.Content}, "document")
    if err != nil {
        return harnessmem.Entry{}, fmt.Errorf("embed: %w", err)
    }
    if len(embeds) == 0 {
        return harnessmem.Entry{}, fmt.Errorf("embed: empty result")
    }

    id, createdAt, err := a.db.StoreMemoryReturning(ctx, a.workspaceID, category, e.Content, origin, embeds[0])
    if err != nil {
        return harnessmem.Entry{}, fmt.Errorf("store: %w", err)
    }

    return harnessmem.Entry{
        ID:        id.String(),
        Content:   e.Content,
        Tags:      e.Tags,
        CreatedAt: createdAt,
        UpdatedAt: createdAt,
        Origin:    origin,
    }, nil
}

// Update tombstones the old row and inserts a new one with re-embedded
// content. Returns the new entry. ErrNotFound if id is unknown.
func (a *HarnessStoreAdapter) Update(ctx context.Context, id string, content string) (harnessmem.Entry, error) {
    if content == "" {
        return harnessmem.Entry{}, harnessmem.ErrInvalidContent
    }
    parsedID, err := uuid.Parse(id)
    if err != nil {
        return harnessmem.Entry{}, harnessmem.ErrNotFound
    }

    // Read existing row to inherit category and origin.
    old, err := a.db.GetMemory(ctx, parsedID)
    if err != nil {
        if err == store.ErrNotFound {
            return harnessmem.Entry{}, harnessmem.ErrNotFound
        }
        return harnessmem.Entry{}, err
    }

    embeds, err := a.embeddings.Embed(ctx, []string{content}, "document")
    if err != nil {
        return harnessmem.Entry{}, fmt.Errorf("embed: %w", err)
    }

    newID, createdAt, err := a.db.StoreMemoryReturning(ctx, a.workspaceID, old.Category, content, old.Origin, embeds[0])
    if err != nil {
        return harnessmem.Entry{}, err
    }
    if err := a.db.DeleteMemory(ctx, parsedID); err != nil {
        // Best-effort tombstone; new row is already written, so the
        // reader semantics ("old ID becomes invalid") still hold for
        // callers that look up by id, but List may return both until
        // the delete eventually succeeds. Log and continue.
        // (See risks §10.)
    }

    return harnessmem.Entry{
        ID:        newID.String(),
        Content:   content,
        Tags:      []string{old.Category},
        CreatedAt: createdAt,
        UpdatedAt: createdAt,
        Origin:    old.Origin,
    }, nil
}

// Remove deletes the row. Idempotent.
func (a *HarnessStoreAdapter) Remove(ctx context.Context, id string) error {
    parsedID, err := uuid.Parse(id)
    if err != nil {
        return nil // unknown id is a no-op per the interface contract
    }
    return a.db.DeleteMemory(ctx, parsedID)
}

// List returns rows ordered by created_at. tag filters by category
// (via tags[0] convention); tag == "" returns all rows for the
// workspace.
func (a *HarnessStoreAdapter) List(ctx context.Context, tag string) ([]harnessmem.Entry, error) {
    rows, err := a.db.ListMemory(ctx, a.workspaceID, tag) // tag == "" → all
    if err != nil {
        return nil, err
    }
    entries := make([]harnessmem.Entry, 0, len(rows))
    for _, r := range rows {
        entries = append(entries, harnessmem.Entry{
            ID:        r.ID.String(),
            Content:   r.Content,
            Tags:      []string{r.Category},
            CreatedAt: r.CreatedAt,
            UpdatedAt: r.UpdatedAt,
            Origin:    r.Origin,
        })
    }
    return entries, nil
}

// Get returns one row by id.
func (a *HarnessStoreAdapter) Get(ctx context.Context, id string) (harnessmem.Entry, bool, error) {
    parsedID, err := uuid.Parse(id)
    if err != nil {
        return harnessmem.Entry{}, false, nil
    }
    r, err := a.db.GetMemory(ctx, parsedID)
    if err != nil {
        if err == store.ErrNotFound {
            return harnessmem.Entry{}, false, nil
        }
        return harnessmem.Entry{}, false, err
    }
    return harnessmem.Entry{
        ID:        r.ID.String(),
        Content:   r.Content,
        Tags:      []string{r.Category},
        CreatedAt: r.CreatedAt,
        UpdatedAt: r.UpdatedAt,
        Origin:    r.Origin,
    }, true, nil
}

// categoryFromTags returns the first recognized category tag, or
// "semantic" as the default. Recognized: episodic, semantic, procedural.
func categoryFromTags(tags []string) string {
    for _, t := range tags {
        switch t {
        case "episodic", "semantic", "procedural":
            return t
        }
    }
    return "semantic"
}

// originFromCtx reads harnessmem.OriginKey, defaulting to "agent".
func originFromCtx(ctx context.Context) string {
    if v, ok := ctx.Value(harnessmem.OriginKey).(string); ok && v != "" {
        return v
    }
    return "agent"
}

// Compile-time check.
var _ harnessmem.MemoryStore = (*HarnessStoreAdapter)(nil)
```

(`time` import is needed transitively only if implementation grows
distinct UpdatedAt handling; remove if unused on first pass.)

## 5. Schema migration

Two additive columns on `memory_entries`. Both nullable; existing rows
get backfilled to safe defaults.

```sql
-- internal/store/schema.sql — append to existing memory_entries table

ALTER TABLE memory_entries
    ADD COLUMN IF NOT EXISTS updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    ADD COLUMN IF NOT EXISTS origin     TEXT        NOT NULL DEFAULT 'agent';
```

`Migrate()` in `internal/store/db.go` runs `schema.sql` idempotently
(uses `IF NOT EXISTS` everywhere), so the migration applies on next
startup with no extra wiring.

### New `*store.DB` methods

Add to `internal/store/memory.go`:

```go
// MemoryRow is one materialized memory_entries row, returned by Get
// and List. Embedding is omitted because adapter callers don't need it.
type MemoryRow struct {
    ID         uuid.UUID
    Category   string
    Content    string
    Origin     string
    CreatedAt  time.Time
    UpdatedAt  time.Time
}

// StoreMemoryReturning inserts a memory entry and returns its ID and
// created_at. Replaces StoreMemory for callers that need the row id.
// (Existing StoreMemory stays for backward compat with the now-removed
// reflect path; this spec leaves it in place — unused after deletion of
// reflect.go, future cleanup.)
func (db *DB) StoreMemoryReturning(ctx context.Context, workspaceID uuid.UUID, category, content, origin string, embedding []float32) (uuid.UUID, time.Time, error)

// GetMemory returns one row by id, or store.ErrNotFound.
func (db *DB) GetMemory(ctx context.Context, id uuid.UUID) (*MemoryRow, error)

// DeleteMemory removes a row by id. Returns nil if id was already gone.
func (db *DB) DeleteMemory(ctx context.Context, id uuid.UUID) error

// ListMemory returns rows for one workspace, optionally filtered by
// category. category == "" returns all categories. Ordered by created_at.
func (db *DB) ListMemory(ctx context.Context, workspaceID uuid.UUID, category string) ([]*MemoryRow, error)
```

`StoreMemory` (the existing 4-arg method) becomes unused after
`reflect.go` is deleted. Leave it for one release, then delete in a
follow-up cleanup commit so the diff stays focused.

## 6. Loop wiring (`internal/loop/loop.go`)

### Construction

`Loop` gains one field:

```go
type Loop struct {
    db        *store.DB
    workspace *store.Workspace
    cfg       *config.Config
    repoPath  string
    provider  llm.LLMProvider
    embedding memory.EmbeddingProvider
    memTool   *harnessmem.MemoryTool // nil when embedding is nil
}

func New(db *store.DB, workspace *store.Workspace, cfg *config.Config, repoPath string, embedding memory.EmbeddingProvider) *Loop {
    var memTool *harnessmem.MemoryTool
    if embedding != nil {
        adapter := memory.NewHarnessStoreAdapter(db, embedding, workspace.ID)
        memTool = harnessmem.NewMemoryTool(adapter)
    }
    return &Loop{
        db:        db,
        workspace: workspace,
        cfg:       cfg,
        repoPath:  repoPath,
        provider:  anthropic.NewAnthropicProvider(os.Getenv("ANTHROPIC_API_KEY"), ""),
        embedding: embedding,
        memTool:   memTool,
    }
}
```

### OnStop hook

Replace the post-`rt.Run` `l.launchReflect(task)` calls with a hook on
the spec. The hook needs the parent runtime handle, so `rt` is
declared *before* `BuildRuntime` and the closure captures it (the same
pattern `examples/self-improving-agent/main.go` uses):

```go
taskCopy := *task // capture by value for the goroutine
var rt *runtime.Runtime

spec := runtime.AgentSpec{
    ID:           task.ID.String(),
    Name:         "Sidecar",
    Model:        models.Coding,
    Workspace:    l.repoPath,
    SystemPrompt: systemPrompt,
    MaxTurns:     20,
    Loop: runtime.LoopConfig{
        Hooks: runtime.LifecycleHooks{
            OnStop: func(_ context.Context, reason string) {
                if reason != "completed" || l.memTool == nil {
                    return
                }
                go l.runReview(rt, taskCopy)
            },
        },
    },
}
rt, err = runtime.BuildRuntime(deps, inputs, spec) // = not := (rt declared above)
```

The reviewer body extracted as a method for testability:

```go
// runReview snapshots the parent runtime and extracts memory via a
// haiku reviewer. Detaches from the parent ctx (which is canceled by
// the time OnStop fires) and applies its own 90s timeout.
func (l *Loop) runReview(parent *runtime.Runtime, task store.Task) {
    ctx, cancel := context.WithTimeout(context.Background(), 90*time.Second)
    defer cancel()

    events, err := l.db.GetTaskEvents(ctx, task.ID)
    if err != nil {
        slog.Warn("review: failed to load task events", "err", err, "task", task.ID)
        return
    }

    // Reviewer registry — write-only (memory tool, no file/bash).
    reviewerReg := tool.NewRegistry()
    reviewerReg.Register(l.memTool)

    res, err := runtime.Review(ctx, parent, runtime.ReviewSpec{
        Prompt:   buildReviewerPrompt(task, events),
        Tools:    reviewerReg,
        Model:    ResolveModels(l.cfg).Triage, // haiku
        MaxTurns: 4,
        Timeout:  60 * time.Second,
    })
    if err != nil {
        slog.Warn("review failed", "err", err, "task", task.ID)
        return
    }
    slog.Info("review completed", "task", task.ID, "actions", len(res.Actions))
}
```

## 7. Reviewer prompt

Built per-task; the reviewer reads the parent's full session as context
and uses the prompt as the review instruction. Mirrors the structure of
the existing `reflectSystemPrompt` but emits tool calls instead of JSON.

```go
// internal/loop/review_prompt.go (new)

const reviewerInstructions = `You are reviewing a just-completed engineering task.
Extract durable knowledge that will help the next time a similar signal arrives.

Use the memory.save tool. Pass tags to categorize each save:
  ["episodic"]   — what was done and the outcome (one save per task, always)
  ["semantic"]   — architectural insights, code conventions, fragile areas
  ["procedural"] — specific commands or workflows that worked

Guidelines:
- Always emit one episodic save summarizing the task.
- Emit semantic/procedural saves only when you learned something not
  derivable from reading the codebase fresh.
- One sentence per save. Keep content concise.
- Do not save anything if the task produced no useful insight.`

func buildReviewerPrompt(task store.Task, events []*store.TaskEvent) string {
    var sb strings.Builder
    sb.WriteString(reviewerInstructions)
    sb.WriteString("\n\nTask context:\n")
    fmt.Fprintf(&sb, "  Signal: %s\n", task.SignalType)
    fmt.Fprintf(&sb, "  Summary: %s\n", task.Summary)
    fmt.Fprintf(&sb, "  Status: %s\n", task.Status)
    if len(events) > 0 {
        sb.WriteString("\nKey events:\n")
        for _, ev := range events {
            if ev.Type == "triage" || ev.Type == "pr_created" || ev.Type == "suggestion" {
                data, _ := json.Marshal(ev.Payload)
                fmt.Fprintf(&sb, "  [%s] %s\n", ev.Type, string(data))
            }
        }
    }
    return sb.String()
}
```

## 10. Risks / open questions

**A. Embedding on the hot path.** `Save` blocks on
`EmbeddingProvider.Embed`. For OpenAI this is ~100-300ms; for the
reviewer's hot path that's acceptable (the reviewer runs in a
background goroutine post-completion). For the foreground coding agent,
each `memory.save` call adds the same latency to its loop — but agents
save sparingly (1-3 saves per task at most), so the budget is fine.
Optimization deferred.

**B. Update tombstone race.** The Update path inserts the new row, then
deletes the old. If the delete fails (db error, ctx canceled), both
rows exist briefly. List will show both; Get on the old id will
succeed. Two mitigations possible:
- Wrap insert+delete in a transaction (preferred but requires plumbing
  tx through pgvector calls — verify pgvector supports it cleanly).
- Best-effort delete with retry queue (rejected: extra complexity).

For v1, accept the brief inconsistency window. The reviewer rarely
calls Update — it usually calls Save for new knowledge. Document the
behavior.

**C. Reviewer model failure modes.** Today's reflect always writes at
least one episodic row via `storeEpisodicFallback`. The new flow
writes nothing if the reviewer doesn't call any tools. This is an
explicit trade per §1: simpler code, same blast radius as a JSON-parse
failure (which today produces only the deterministic episodic row, not
any of the agent's actual insights). If this proves too aggressive in
practice, a fallback path can be re-added in a future spec.

**D. Foreground saves while reviewer is running.** If the agent saves
mid-task and the OnStop reviewer fires immediately after, both write
through the same adapter. The pgvector `*store.DB` is already
concurrency-safe (pgx pool); no additional mutex needed. The tag-as-
category mapping is deterministic so concurrent saves don't conflict.

**E. Triage-model JSON output.** Sidecar's triage path
(`internal/triage/triage.go`) still parses a JSON envelope. This spec
does not touch triage; whether to migrate triage to a tool-call shape
is a separate decision (probably no — triage is a one-turn classifier,
not an agent loop, so the JSON shape fits).

**F. Memory garbage collection.** Neither today's reflect nor this
adapter prunes old entries. As workspaces age, `memory_entries` grows
unbounded. Out of scope for this spec; a separate "memory compaction"
spec should address it (likely: pgvector similarity-based dedup +
recency decay).

## 11. Out of scope (deliberately deferred)

- **Skills.** `tool/skills` adoption gets its own spec. Procedural
  memory entries written by the new flow are still rows in
  `memory_entries`, not skill files.
- **Policies as tool calls.** The reviewer cannot write policies in
  this design — they remain operator-curated YAML or the existing
  `db.StorePolicy` admin path.
- **MCP integration.** Phase 5 (additional adapters via MCP) is a
  separate effort.
- **Per-tag retrieval.** The pre-loop retrieval still uses category as
  the discriminator. Multi-tag filtering would require schema work
  (the `tags TEXT[]` column proposed in §4 alternatives) and is
  deferred.
- **Auxiliary provider routing.** `ReviewSpec.Provider` is left nil so
  the reviewer inherits the parent's provider. If sidecar later wants
  to route the reviewer to a different endpoint (e.g., a local model),
  set `Provider` and `Model` together.

## 13. Open questions for review

1. **Update transaction boundary** (§10B) — accept brief inconsistency
   for v1, or invest in tx plumbing now? Recommendation: accept,
   document, revisit if it causes a production issue.
2. **Foreground memory tool in suggest-only mode** (§6) — the spec
   currently registers `memTool` regardless of autonomy level. Should
   suggest-only suppress writes too? Recommendation: leave registered.
   Suggest-only restricts file writes, not knowledge curation.
3. **Reviewer MaxTurns budget** (§6) — 4 turns chosen as a guess.
   Verify in live test that haiku finishes within 4 turns for typical
   sessions; bump to 6-8 if not.
